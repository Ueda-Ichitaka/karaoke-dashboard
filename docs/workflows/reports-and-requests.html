Reports and requests

How a report of a broken song or a request for a new one gets from a singer through review and the USDX Song Factory into the library, and how the dashboard notices the fix. Details: features.md, csv.md.

Step by step

  1. Singer

    Reports a broken song on /report or requests one on /request. The form's profile - karaoke night or strict, set on Settings - decides what's required. A second report for a song merges into its open one; a request for a song that's already in the library or already requested is refused.

  2. Dashboard

    The submission waits in Needs review (pending_broken_reports, pending_song_requests). From now on the song carries the Reported broken badge on Songs and What's new.

  3. Contributor or admin

    Completes it with Edit - language, lyrics link, genre and trait tags - and Admits it into the list; the admit rules are fixed, whatever the form's profile. Or Discards it; a report can also go straight into the list as Resolved.

  4. Reported and Requested tabs

    Export open CSV or Export all CSV downloads broken.csv and song-requests.csv. Import CSV takes the same formats back - every row lands in Needs review or merges into an existing entry.

  5. You

    Save both files into the Factory's stack/input/, then ./factory.sh pull-repairs --apply (copies the reported songs from the library) and ./factory.sh up. Rows already done are skipped, so full exports are fine.

  6. You

    Sing-test the results in USDX and copy the folders of output/new/ and output/repaired/<repair>/ into the library.

  7. Library scan

    The next scan (daily, or Scan now on Settings) reads the new write times: the report gets Updated since report, the song shows on What's new, and in the "until updated" badge mode the badge goes.

  8. Contributor or admin

    Checks the song and sets the report Resolved, the request Done - the badge goes in any mode.
