Library checks and scripts

The dashboard never changes a song file. Its Duplicates and Integrity pages find what's wrong and export playlists and move lists; the scripts in scripts/ and UltraStar Manager fix the files, by hand. Details: features.md, library-scripts.md.

Step by step

  1. Duplicates

    Scans every song file's artist and title once a month (day 1, 03:00 - DUPLICATES_RESCAN_*) or on Rescan, and keeps the result in memory: duplicates, possible duplicate versions, and folders without a song file (a .txt with #BPM).

  2. Contributor or admin

    Opens a group with Review (a field-by-field comparison) and either removes the extra copy from the library by hand or Dismisses the group - stored in dismissed_duplicates, it stays dismissed after a rescan.

  3. Integrity

    Checks on every view: each song file against the UltraStar format, the folders against the "Artist - Title" convention, and songs sitting in the wrong folder.

  4. Admin

    Exports the format issues as a .upl playlist for UltraStar Manager, and the structure and misplaced checks as move lists (non-conforming.moves, misplaced.moves).

  5. You

    Runs the scripts against the real library, outside the container, --dry-run first: fix_case_mismatches.py, then repair_library.py --csv repairs.csv, and apply_moves.sh with the move lists. Fixes the playlist's songs in UltraStar Manager.

  6. Reported tab

    Import CSV takes the rows repair_library.py couldn't fix - they continue as reports (see reports and requests).
