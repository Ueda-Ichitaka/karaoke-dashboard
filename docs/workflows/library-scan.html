Library scan and What's new

The library has no "added" dates of its own, so a scan looks at it regularly and records what changed. What's new, the Reported page, the Reported broken badge and the Genres page only read what it recorded. Details: features.md.

Step by step

  1. Trigger

    The scan runs on the schedule saved on Settings (a cron expression, daily at 11:00 by default), once at app start (LIBRARY_SCAN_ON_START), or when an admin presses Scan now. Reset forgets every recorded date first. Only one scan runs at a time.

  2. Read

    It lists the library's top-level folders and, per folder, the write time and size of the .txt, .mp3 and .opus files directly in it - leaving out the Factory's helper files - and the #GENRE tag of every song file. An unreadable or unmounted library records nothing.

  3. Record

    A folder it has never seen is added (not on the very first scan, which counts everything as old; a renamed folder counts as new). A changed write time or size, or a new file, is an update, dated by that file's write time; writes within an hour after adding are part of adding. Deleting a file is not an update. The newest write time is kept in last_write_at.

  4. Genres

    Each folder's genres replace its rows in song_genres. An open genre edit whose genres the files now name (same order, any case) is deleted - the Factory has written it.

  5. Readers

    What's new lists folders added and updated within the period from Settings; the Reported page marks reports Updated since report; the Reported broken badge in "until updated" mode leaves fixed songs out; the Genres page shows song_genres, an open edit instead.

What it never does

read-only
Files
the scan only reads; the library is mounted read-only
Dates
it can't know when a folder arrived before its first scan - those count as old
Deletes
a deleted file or folder is no update and no removal
